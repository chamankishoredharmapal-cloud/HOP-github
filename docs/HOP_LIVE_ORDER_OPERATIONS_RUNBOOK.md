## 2. Payment Reconciliation & Order Matching

### 2.1 Authoritative Linkage Architecture

Every customer purchase links three identifiers across systems:
1. **HOP Order Number:** Formatted as `HOP-YYYYMMDD-XXXXXX` (e.g., `HOP-20261015-000001`), visible to customer and in Studio.
2. **HOP Order UUID (`orders.id`):** Internal relational primary key linking `order_items`, `customers`, and `shipping_addresses`.
3. **Razorpay Order ID (`payments.razorpay_order_id`):** Formatted as `order_xxxxxxxxxxxxxx`, created by `create-razorpay-order`.
4. **Razorpay Payment ID (`payments.razorpay_payment_id`):** Formatted as `pay_xxxxxxxxxxxxxx`, generated by Razorpay upon successful charge.

### 2.2 Finding an Order from a Razorpay Payment ID

If a customer quotes a payment ID (`pay_xxxxxxxxxxxxxx`):
1. In Studio -> **Orders** (`/studio/orders`): Search by customer email or order number.
2. If direct database query is required (via Supabase SQL Editor):
   ```sql
   SELECT o.id, o.order_number, o.status, o.payment_status, o.total,
          p.razorpay_payment_id, p.amount, c.email, c.full_name
   FROM orders o
   JOIN payments p ON o.id = p.order_id
   JOIN customers c ON o.customer_id = c.id
   WHERE p.razorpay_payment_id = 'pay_xxxxxxxxxxxxxx';
   ```

### 2.3 Resolving State Mismatches (Pending vs Paid)

If Razorpay reports payment **Captured** but HOP Order shows **Pending Payment**:
* **Root Cause:** Webhook delivery was delayed, or customer closed browser before `verify-payment` returned.
* **Resolution Procedure:**
  1. Inspect Razorpay Dashboard -> **Webhooks** (`https://dashboard.razorpay.com/app/webhooks`): Check delivery status of `payment.captured`.
  2. If webhook failed or was not delivered, click **Resend Webhook**.
  3. Alternatively, manually reconcile by executing the safe, idempotent confirmation RPC in Supabase SQL editor:
     ```sql
     SELECT public.confirm_paid_order(
       p_razorpay_order_id := 'order_xxxxxxxxxxxxxx',
       p_razorpay_payment_id := 'pay_xxxxxxxxxxxxxx'
     );
     ```
  4. Verify that `orders.payment_status` updates to `paid` and `orders.status` updates to `confirmed`.

## 3. Webhook Troubleshooting & Event Logs

### 3.1 Webhook Configuration Reference

* **Endpoint URL:** `https://kbvjmcnaaogkbnerjcoc.supabase.co/functions/v1/razorpay-webhook`
* **Secret Configuration:** Managed in Supabase Vault as `RAZORPAY_WEBHOOK_SECRET`.
* **Subscribed Events:**
  * `payment.captured` $\rightarrow$ Triggers `confirm_paid_order()` and dispatches order confirmation email.
  * `payment.failed` $\rightarrow$ Marks payment as failed and restores reserved stock via `release_order_inventory()`.
  * `order.paid` $\rightarrow$ Fallback payment confirmation.

### 3.2 Diagnostic Steps for Webhook Errors

1. **HTTP 400 (`invalid_signature`):**
   * Indicates the signature in `x-razorpay-signature` did not match `RAZORPAY_WEBHOOK_SECRET`.
   * **Action:** Verify that the webhook secret entered in Razorpay Dashboard matches the secret configured in Supabase Secrets. Never disable signature verification.
2. **HTTP 200 (`already_processed: true`):**
   * Normal idempotency behavior. The event was already recorded in `payment_events` table and safely ignored.
3. **HTTP 500 (`configuration_error`):**
   * Indicates `RAZORPAY_WEBHOOK_SECRET` is missing from the Edge Runtime environment.

## 4. Refund & Cancellation Procedures

### 4.1 Order Cancellation Within 1-Hour Window

Under House of Padmavati policy, customers may cancel qualifying orders within 1 hour of placement before dispatch preparation begins.
1. Customer initiates cancellation in `/account/orders/:id` OR contacts concierge.
2. In Studio `/studio/orders/:id`, verify that `created_at` is within 60 minutes and `status = 'confirmed'`.
3. Process refund in Razorpay Dashboard:
   - Navigate to Razorpay Dashboard -> **Payments** -> Select `pay_xxxxxxxxxxxxxx`.
   - Click **Issue Refund** -> Select **Full Refund** -> Reason: `Customer Requested Cancellation`.
4. In Studio -> Mark Order status as **Cancelled**.
5. The cancellation automatically releases reserved inventory back to catalog stock:
   ```sql
   SELECT public.release_order_inventory(
     p_order_id := '<order-uuid>',
     p_reason := 'customer_cancellation'
   );
   ```

### 4.2 Return & Post-Delivery Refund Policy

* Return window: **3 days** from delivery for 1–3 products; **7 days** for >3 products.
* Condition: Saree must be unworn, in original bespoke box packaging with intact authentic tags.
* When return physical inspection passes atelier verification:
  1. Open Razorpay Dashboard -> Issue refund for the specific transaction amount.
  2. Update HOP Studio order status to `returned`.
  3. Re-inventory the piece via Studio `/studio/products` by logging a `restock` adjustment.

## 5. Inventory Auditing & Discrepancy Investigation

### 5.1 Tracing Stock Adjustments

All inventory movements are recorded immutably in `public.inventory_history`.
To audit all movements for a specific saree:
```sql
SELECT ih.created_at, ih.change, ih.previous_stock, ih.new_stock, ih.reason, ih.notes, p.name
FROM inventory_history ih
JOIN products p ON ih.product_id = p.id
WHERE p.id = '<product-uuid>'
ORDER BY ih.created_at DESC;
```

### 5.2 Stock Audit Reason Codes

* `'order_created'`: Stock reserved when customer initiated checkout (`change = -1`).
* `'sale'`: Confirmed permanent deduction when payment succeeded (`change = 0`, confirming reservation).
* `'payment_failed'` / `'release'`: Stock restored to catalog because checkout expired or failed (`change = +1`).
* `'customer_cancellation'`: Stock restored following authorized cancellation (`change = +1`).
* `'restock'`: New pieces received from weaving atelier (`change = +N`).
* `'adjustment'`: Owner/Admin manual correction in Studio.

## 6. Frontend Deployment Rollback Procedure

If a bad frontend release causes checkout or visual regressions:
1. **Zero Downtime Edge Rollback:**
   - Log into Cloudflare Dashboard -> **Workers & Pages** -> `houseofpadmavati`.
   - Under **Deployments**, locate the last known-good production deployment (e.g., `23d6415` or previous certified deployment).
   - Click the three dots (`...`) next to the deployment $\rightarrow$ Click **Rollback to this deployment**.
   - Edge rollback completes globally in under 60 seconds without rebuilds.
2. **Database Integrity Preserved:**
   - Rolling back the frontend SPA does NOT roll back or mutate database records, customer carts, or payments.
